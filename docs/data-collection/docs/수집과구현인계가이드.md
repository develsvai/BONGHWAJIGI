# 재난 데이터 수집과 구현 인계 가이드 Mac

Mac 작업 환경  |  코디세이 해커톤  |  기준일 2026년 10월 30일

이 문서는 데이터 수집 담당자가 확보한 자료를 모델·서버·앱 구현 담당자에게 전달하기 위한 실행 안내서다. 첨부 자료의 위치, 같은 결과를 재현하는 방법, 인증이 필요한 수집 방법, 모델 입력으로 사용하기 전에 보완할 항목을 설명한다.

현재 자료는 수집처 카탈로그와 연결 검증용 표본이다. 산불 확산 학습용 데이터셋을 완성하려면 시간별 기상, 지형·연료, 시각이 확인된 실제 화재경계를 추가로 확보해야 한다. 구룡마을은 가건물 밀집 화재이므로 산림 산불의 확산 정답으로 일반화하지 않는다.

## Mac 환경에서 자료 열기와 실행하기

ZIP을 Finder에서 풀면 disaster_handoff_mac 폴더가 생성된다. 작업 폴더로 이동할 때 터미널에 cd와 공백을 입력한 뒤 해당 폴더를 끌어 넣으면 경로의 공백·한글을 잘못 입력하는 일을 줄일 수 있다. 이 패키지는 Apple Silicon과 Intel에 특화된 바이너리를 포함하지 않는다.

```zsh
python3 --version
python3 scripts/collect_data.py replay
```

Python은3.10 이상을 사용한다. 명령이 없거나 버전이 낮으면 python.org의 macOS 배포본을 설치한다 [1]. 표준 라이브러리만 사용하므로 pip 설치와 가상환경은 필수가 아니다. 실행은 Finder 더블클릭보다 터미널을 권장한다.

| 폴더 또는 파일 | 용도와 여는 방법 |
| --- | --- |
| docs/수집과구현인계가이드.docx | Word 또는 Pages에서 읽고 수정한다. |
| docs/수집과구현인계가이드.md | 텍스트 편집기에서 읽고 명령을 복사한다. |
| scripts/collect_data.py | 터미널에서 python3로 실행하는 수집 예제다. |
| scripts/verify_snapshot.py | 보관 원본의 SHA256을 재검사한다. |
| data/raw/ | 확장자를 붙인 실제 CSV·JSON·HTML·XML 응답이다. |
| data/catalog/ | 기존 XLSX·CSV·사례 타임라인·광역 샘플이다. |
| data/raw_manifest.json | 원본 파일과 출처 URL·요청시각·해시를 연결한다. |
| data/field_contract.json 및 next_tasks.csv | 필드 규약 제안과 추가 확보 작업 목록이다. |

CSV는 UTF-8이다. Excel·Numbers에서 좌표, 관측시각, 식별자의 형식을 확인한다. acq_time은0030 같은 값이 있으므로 원본 필드는 텍스트로 읽는다. 원본을 열어 저장하면서 시각·선행0을 바꾸지 말고 복사본에서 확인한다.

replay 결과는 runs/replay_시각/에 생성된다. 이전 결과가 들어 있는 출력 폴더에는 덮어쓰지 않는다. 새 폴더명을 지정하거나 기본값으로 다시 실행한다.

## FIRMS 보관본으로 조회 결과 재현하기

FIRMS 최근7일 파일은 시간이 지나면 내용이 바뀐다. 이번 사례의 재현에는 data/raw의2026년10월30일 보관본을 사용한다. replay는 먼저 파일 해시와 필수 헤더를 검사하고 UTC 관측시각을 KST로 바꾼 뒤 시간·좌표를 필터링한다 [2].

```zsh
python3 scripts/collect_data.py replay \
  --start 2026-10-27 --end 2026-10-29 \
  --bbox 127.04 37.46 127.09 37.50
```

기간은 KST10월27일00시 이상, 29일00시 미만이다. bbox는 서쪽경도·남쪽위도·동쪽경도·북쪽위도 순이다. 지정 사각형은 연구용 검색영역이며 공식 발화점이나 화재경계가 아니다.

| 원본 파일 | 전지구 원본행 | 대조영역행 | 사례영역행 |
| --- | --- | --- | --- |
| MODIS_C6_1_Global_7d.csv | 74,400 | 9 | 0 |
| SUOMI_VIIRS_C2_Global_7d.csv | 414,040 | 128 | 0 |
| J1_VIIRS_C2_Global_7d.csv | 427,290 | 165 | 0 |
| J2_VIIRS_C2_Global_7d.csv | 397,898 | 77 | 0 |

대조영역은 경도124~132, 위도33~39의 넓은 사각형이다. 한국 행정경계가 아니며 일본·북한·해역 등을 포함한다. 379행은 반복 관측과 다른 열원을 포함할 수 있는 탐지 레코드이며 독립 화재379건을 의미하지 않는다.

| 주요 필드 | 해석과 주의점 |
| --- | --- |
| latitude / longitude | WGS84 위도·경도. GeoJSON에는 longitude, latitude 순으로 넣는다. |
| acq_date / acq_time | UTC 관측일·시각. 4자리HHMM으로 읽고 원문을 보존한다. |
| confidence / frp | 센서별 신뢰도 정의를 유지한다. FRP 단위는MW이며 피해면적이 아니다. |
| scan / track / satellite | 픽셀 크기와 위성 정보를 보존한다. 픽셀 사각형 전체가 연소했다는 뜻은 아니다. |

FIRMS_case.csv는 헤더만 있는0행 파일이다. query_summary.json에 필터·원본행수·날짜범위·해시·상태가 함께 저장된다. 0건을 화재가 없다는 정답 라벨로 사용하지 않는다 [3].

## 인증키가 필요한 기상과 재난문자 수집하기

### 기상청 시간별 관측 표본

기상청 ASOS 시간자료 서비스의 활용신청·승인 후 키를 환경변수 KMA_SERVICE_KEY로 설정한다 [4]. 아래 명령은 Mac 기본 zsh에서 키를 화면에 보이지 않게 입력한다. 입력 뒤 Return을 누른다. 발급받은 디코딩 키를 사용하고 사전 URL 인코딩을 중복 적용하지 않는다.

```zsh
read -s "KMA_SERVICE_KEY?기상청 키 입력: "
export KMA_SERVICE_KEY
python3 scripts/collect_data.py asos-sample
unset KMA_SERVICE_KEY
```

표본 요청은 서울108 지점, KST10월27일00시~28일23시, pageNo=1, numOfRows=100이다. 응답의 결과코드·totalCount·tm·지점·단위·품질플래그를 확인한다. 서울108은 구룡마을 현장 관측소가 아니므로 최근접 AWS와 운영이력을 추가 검토한다. 키 미보유로 실제 성공 응답은 미검증이다.

### 행정안전부 긴급재난문자 표본

재난안전데이터 공유플랫폼에서 긴급재난문자를 신청하고 승인키를 받는다 [5]. 현재 명세는 V2/api/DSSP-IF-00247이며, 과거 DisasterMsg2 예제를 그대로 사용하지 않는다. 키는 SAFETYDATA_SERVICE_KEY로 설정한다.

```zsh
read -s "SAFETYDATA_SERVICE_KEY?재난문자 키 입력: "
export SAFETYDATA_SERVICE_KEY
python3 scripts/collect_data.py messages-sample
unset SAFETYDATA_SERVICE_KEY
```

요청은 crtDt=20261027, rgnNm=서울특별시 강남구의 첫100건 표본이다. crtDt는 조회 시작일이다. 응답 CRT_DT를 읽어10월29일00시 이전만 선택하고 전체 페이지를 수집해야 한다. 다른 발송기관·광역지역 문자 누락을 막으려면 전국 조회도 대조한다.

표본 모드는 response.json과 키를 가린 request_log.json만 저장하며 학습용 정규화를 완료하지 않는다. HTTP200도 업무상 오류일 수 있다. 이 예제에는 전체 페이지 순회·자동 재시도·운영 모니터링이 구현되어 있지 않다. 구현 담당자가 정상 응답 구조와 쿼터를 확인해 확장한다.

## 위성 검색과 원본 보존하기

### Sentinel 카탈로그와 실제 영상 구분

```zsh
python3 scripts/collect_data.py sentinel-search
```

예제는 Sentinel-2의 UTC10월25일00시~30일00시, 사례 검색영역과 교차하는 제품을 OData로 검색한다. ContentDate는 관측, PublicationDate는 공개시각이며 각각 보관한다. value·@odata.count·@odata.nextLink를 확인하고 다음 페이지가 있으면 끝까지 조회한다 [6].

보관본에는 Sentinel-2 2제품과 Sentinel-1 7제품이 있다. S2 L1C와L2A는 같은 촬영의 처리수준 차이다. S1 RAW는 별도 처리 전 원시자료이며 SLC 등과 중복 촬영을 포함할 수 있다. 제품 수를 독립 관측 횟수로 세지 않는다. 검색 표본은 인증 없는 메타조회이며 원영상 다운로드와 피해판독은 별도 작업이다.

S2 보관본의 ContentDate 시작은10월28일02:18:09 UTC, L2A 공개는05:09:20 UTC다. 촬영은 완진 보도 이후이며 타일별 실제 촬영시각은 영상 내부 메타로 추가 확인한다. 장면 전체 구름율로 현장 픽셀의 구름 유무를 확정할 수 없다.

### 수집 상태와 실패 처리

| 상태 | 판정 기준 |
| --- | --- |
| 수집완료 | 응답 형식·기간·필드를 검사하고 원본을 보관했다. 메타만 확보했다면 메타 수집완료로 표시한다. |
| 0건 | 정상 자료가 조회기간을 포함하고 필터를 수행한 결과가0행이다. |
| 미수집 | 키누락·통신실패·파일미확보 등으로 대상 원자료가 없다. |
| 미검증 | 명세·범위·업무코드·페이지·이용조건 등을 확인하지 못했다. |

HTTP200만으로 성공 처리하지 않는다. 실제 NOAA 요청은 HTML이어서 관측 CSV로 배제했다. 인증 실패와 기간 미포함을0건으로 바꾸지 않는다. 날짜범위가 걸쳐 있다는 검사도 센서 통과·모든 파일의 완전성을 보증하지는 않는다.

SSL 오류가 나면 Mac의Python 배포본과 인증서를 확인한다. python.org 배포본은 해당 설치폴더의 Install Certificates.command를 제공한다 [1]. 검증을 끄는 방식으로 통과시키지 않는다. 401/403은 승인·키, 429는쿼터, 5xx는기관 장애 여부를 확인한다.

## 모델팀과 합의할 필드와 파일 구조

원본과 가공본을 분리하고 data/field_contract.json을 모델팀과 합의한다. 다음 규약은 제안이며 실제 API가 이 이름으로 응답한다는 뜻이 아니다. 단위·좌표계·시간대·결측 의미를 원본에서 추적할 수 있어야 한다.

| 필드 | 형식 | 전달 원칙 |
| --- | --- | --- |
| record_id / source_id | 문자열 | 원천 식별자·관측시각·위치·제품버전을 보존해 중복키를 정한다. |
| event_id | 문자열 또는null | 사건 연결을 확인하기 전에는null이다. |
| data_kind | 구분값 | observation, forecast, warning 등 자료 성격을 분리한다. |
| observed_at_utc | ISO8601 또는null | 관측 또는 사건시각이다. 원천의 시간정밀도를 보존한다. |
| issued_at_utc / valid_at_utc | ISO8601 또는null | 발표시각과 예보유효시각을 분리한다. |
| collected_at_utc | ISO8601 | 새 수집기는 요청시작·수신완료도 함께 기록한다. |
| geometry | GeoJSON 또는null | EPSG4326 경도·위도 순. 원좌표계도 따로 기록한다. |
| measurement | 객체 | value, unit, quality_flag를 변수마다 보존한다. |
| raw_ref / license_ref | 문자열 또는null | 원본상대경로·해시·이용조건과 연결한다. |

### 시간과 좌표 예시

```python
acq_date = "2026-10-26"
acq_time = "1913"
observed_at_utc = "2026-10-26T19:13:00+00:00"
observed_at_kst = "2026-10-27T04:13:00+09:00"
geometry = {"type": "Point",
            "coordinates": [131.64163, 33.26466]}
```

위 값은 광역 FIRMS 표본의 실제 첫 레코드다. 위치는 일본 쪽이며 구룡마을 데이터가 아니다. 이 예시는 시간변환과 GeoJSON 좌표순서를 확인하기 위한 것이다. 원천 confidence=46과frp=5.83은 MODIS의 필드 의미대로 유지한다.

숫자0, 결측null, 원문의대시 표기는 다르게 저장한다. 기상 일자료의 강수대시는 원문으로 남겼고0mm로 대체하지 않았다. 여러 기관의 같은 위성자료를 독립 근거처럼 중복 집계하지 않는다.

## 학습용 사건 데이터셋으로 보완하기

먼저 모델팀이 예측할 출력과 시간·공간 간격을 정한다. 예를 들어30분 뒤 화재경계, 격자별 위험점수, 경로 영향 여부는 필요한 정답과 입력이 다르다. 아래 항목은 산불 확산 입력을 마련하기 위한 수집 기준이며 모델 선택에 따라 조정한다 [7].

| 필요 자료 | 현재 상태 | 추가 수집과 완료 기준 |
| --- | --- | --- |
| 발화 위치와 시각 | 사례 정확좌표 미확정 | 공식 발화·신고시각을 구분하고 좌표 출처·오차를 기록한다. |
| 시간별 기상 | 일자료2일 확보 | 풍향·풍속·습도·기온·강수와 관측소 위치·품질플래그 확보. |
| 지형과 연료 | 카탈로그 후보 | DEM·토지피복·임상 등 선택모델 필드와 제작시점 확보. |
| 확산 정답 | 시간별 경계 미확보 | 시각별 실제 경계 또는 평가에 사용할 최종 피해경계를 확보한다. |
| 다수 산림 산불 사례 | 미선정 | 사건별 입력·정답을 맞추고 학습·검증·시험 사건을 분리한다. |
| 대피 지시와 시설·통제 | 공식 원문 일부 미확보 | 문자SN·발송시각·도로통제·시설 개방기준시각을 확인한다. |

구룡마을은 도시 가건물 화재이므로 산림 연료모델의 학습사례와 별도로 관리한다. FIRMS0건은 열이상 미탐지 조건을 보여주지만 확산 경계 정답을 제공하지 않는다. 정답이FIRMS에서 파생됐다면 같은FIRMS 입력으로 평가한 결과를 독립 검증으로 해석하지 않는다.

### 구현 완료를 확인할 항목

- 보관본 해시가 모두 일치하고 replay 결과가 사례0행·대조영역379행이다.

- 키가 있는 표본 요청에서 업무코드·전체건수·페이지·종료일 필터를 확인했다.

- 데이터·모델 입력·정답의 시각을 맞추고 예측 당시 공개되지 않은 자료를 입력에서 제외했다.

- 원본과 가공본·소스버전·단위·품질·이용조건이 연결되며 미확보값을0으로 채우지 않았다.

- 공식 대피지시·현장통제·시설 운영상태를 확인했다. 일반 지도경로를 안전 확정 경로로 표시하지 않는다.

## 인계 순서와 검증 범위

### 역할별 권장 진행 순서

수집 담당자는 카탈로그와 보관본을 전달하고, 모델팀은 예측 대상·필수 입력·정답 기준을 정한다. 수집 담당자가 승인키·사례별 입력·정답을 확보하면 구현 담당자는 공통 필드로 변환하고 운영 수집을 연결한다. 구체적 작업과 완료 기준은 data/next_tasks.csv에 기록했다. 담당자와 일정은 팀이 배정한다.

현재 검증은 Windows의 Python에서 보관본 해시·FIRMS 재현·오류구분을 확인하는 범위다. 스크립트는 Mac에서도 사용할 표준 라이브러리와 상대경로로 작성했으나 실제 Mac 기기 실행은 미검증이다. 인증키를 사용하는 모드는 키 미보유로 성공응답을 검증하지 못했다. 원영상 다운로드·운영 재시도·모델·앱 구현은 별도 작업이다.

### 최신 자료를 다시 받을 때

```zsh
python3 scripts/collect_data.py firms-live \
  --start YYYY-MM-DD --end YYYY-MM-DD
python3 scripts/verify_snapshot.py
```

firms-live의 날짜는 실행 시점 최근7일 파일이 포함하는 KST 기간으로 치환한다. 약108MB 규모의 CSV를 받을 수 있으며 크기는 달라진다. 과거2026년10월27~28일은 나중의 최신파일에 없을 수 있다. 그런 경우 기간 미검증으로 표시하고 보관본 또는 FIRMS Archive/Area를 사용한다 [2]. verify_snapshot은 첨부 보관본만 검사한다.
