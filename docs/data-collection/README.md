# 재난 데이터 수집 자료

이 폴더는 봉화지기 데이터 수집 담당자가 카탈로그·실제 표본·연결 검증 결과를 계속 갱신하는 공간입니다. 자료 수집 기준일은 **2026-10-30**, 저장소 인계 구성일은 **2026-10-31**입니다. 정리 문서는 학습용 데이터셋이나 운영 수집 완료를 의미하지 않습니다.

## 최신 검수: 산불 MVP · 10분 갱신 (2026-10-31)

산불 MVP의 자료 선택은 [10분 갱신 검수 가이드](reviews/20261031/산불MVP_10분갱신_검수가이드.md)와 [재검수 엑셀](reviews/20261031/산불MVP_10분기준_재검수.xlsx)을 먼저 봅니다. 기존 전체 재난 카탈로그35개를 재분류하고 천리안 2A 산불탐지 FF 1개를 추가했습니다. [동일 CSV](reviews/20261031/산불MVP_10분기준_재검수.csv), [지연 측정용 빈 양식](reviews/20261031/갱신지연_측정기록_빈양식.csv), [공식 문서 재조회 기록](reviews/20261031/공식문서_재조회기록.json)도 제공합니다.

- **1순위:** 기관/API 갱신10분 이내가 공식 명시된 산불 관련 자료. 긴급재난문자 메타데이터1분. 실제 발송→API 전달 지연은 미검증입니다.
- **2순위:** AWS 매분 관측, 천리안 FF10분 제품, 초단기예보, 강풍·건조 특보, 도로 통제 등. 생산·발표 주기가 짧더라도 API 공개 지연이 불명확하면 우선 측정합니다.
- **보완·보류:** GDACS 대표 피드6분은 국제 대형재난 보완용입니다. 산림청 발생통계는 실시간 표기와 분기 집계 설명 충돌로 보류합니다.
- **보조·기본자료:** FIRMS 한국 전지구NRT는 관측 후3시간 이내여서10분 실시간 핵심 자료에서 제외합니다. 정적 지형·임상·시설 위치·기본 지도는 별도로 유지합니다.

현재 운영에서10분 이내 수신이 검증된 소스는 없습니다. 이번 결과는 공식 문서·기존 기록 재검수이며 승인키 성공 응답이나 연속 실측 완료가 아닙니다. 기존 구룡마을 도시화재 사례와 FIRMS0행은 과거 수집 결과 그대로 보존합니다.

## 읽는 순서

1. [Mac 수집과 구현 인계 가이드](docs/수집과구현인계가이드.md)를 읽습니다. [Word 문서](docs/수집과구현인계가이드.docx)도 제공합니다.
2. [35개 데이터 카탈로그](data/catalog/데이터카탈로그.csv)와 [연결 예제](data/catalog/연결예제.csv)에서 대상 소스의 인증·시공간 범위·검증 상태를 확인합니다.
3. [사례 수집 현황](data/catalog/사례수집현황.csv), [사건 타임라인](data/catalog/사건타임라인.csv), [FIRMS 광역 표본](data/catalog/FIRMS_국내주변광역_샘플.csv)을 확인합니다.
4. [필드 규약 제안](data/field_contract.json)과 [추가 작업](data/next_tasks.csv)을 모델·서버·앱 담당자와 합의합니다.

이 폴더의 문서는 [기존 데이터 흐름](../architecture-and-data-flow.md)과 [AI 역할 및 검증 범위](../ai-and-infrastructure.md)를 위한 수집 자료입니다. 예측 모델·정책·경로 알고리즘을 확정하거나 LLM의 자료 판단 범위를 확대하지 않습니다.

## Mac에서 실행하기

저장소 최상위 폴더에서 실행합니다. Python3.10 이상과 표준 라이브러리만 필요합니다.

```zsh
python3 docs/data-collection/scripts/collect_data.py --help
```

### 보관본을 복원한 뒤 재현

저장소의 기존 `.gitignore`에 따라 `data/raw/`와 원본 대용량 파일은 Git에 포함하지 않습니다. 전지구 FIRMS CSV4종만 약108MB입니다. 과거 보관본은 자료 담당자가 별도로 전달한 `Mac_재난데이터_구현인계_20261030.zip`에 있습니다. 최신 URL을 다시 받는 것만으로 과거 보관본을 복원할 수는 없습니다.

먼저 전달받은 ZIP을 Finder에서 풉니다. 아래 첫 번째 경로는 실제 압축 해제 폴더에 맞게 바꾸며, 대상 폴더에 기존 원본이 있다면 해시를 비교한 후 별도로 보관합니다.

```zsh
# 저장소 최상위에서 실행. 첫 경로는 전달받은 패키지 위치로 변경
cp -R "/path/to/disaster_handoff_mac/data/raw" docs/data-collection/data/
python3 docs/data-collection/scripts/verify_snapshot.py
python3 docs/data-collection/scripts/collect_data.py replay
```

정상 보관본은15개 파일 해시가 일치하고, 기본 replay는 사례0행·대조영역379행을 생성합니다. 결과는 `docs/data-collection/runs/`에 저장되며 Git에서 제외합니다. 원본이 없으면 replay를 실행하기 전에 보관본을 먼저 복원하십시오.

### 최신 공개 자료와 승인키 자료

`firms-live`는 실행 당시 최근7일 자료를 받습니다. 조회기간을 해당 파일에 포함되는 날짜로 지정해야 합니다. `sentinel-search`는 카탈로그 메타만 조회합니다. `asos-sample`과 `messages-sample`은 각각 `KMA_SERVICE_KEY`, `SAFETYDATA_SERVICE_KEY` 환경변수가 필요하며 첫 페이지 표본만 저장합니다.

전체 페이지, 업무 오류코드, 종료일 필터, 쿼터, 자동 재시도, 운영 모니터링은 [가이드](docs/수집과구현인계가이드.md)를 확인해 구현해야 합니다. 승인키 성공 요청과 실제 Mac 기기 실행은 아직 미검증입니다. 기존 실행 검증 환경은 [검증 기록](data/validation_report.json)에 남겨 두었습니다.

## 계속 자료를 올리는 규칙

- 자료를 추가·수정하는 커밋에는 이 README의 최신 링크·자료 기준일·갱신 기록·검증 상태와 남은 작업을 함께 반영합니다. 상위 `docs/README.md`의 수집 안내도 최신 자료로 연결합니다.
- 카탈로그·샘플·수집 예제·사례별 설명을 이 폴더에 추가합니다. Markdown을 기준 문서로 유지하고 Word·XLSX를 갱신했다면 버전 날짜를 함께 기록합니다.
- 각 표본에 원천URL, 관측/발표/수집시각, 원좌표계·단위·품질·가공과정·사용조건을 남깁니다. 원본 해시는 [manifest](data/raw_manifest.json)로 추적합니다.
- `수집완료`, `0건`, `미수집`, `미검증`을 구분합니다. 기존 확정값을 덮어쓰지 말고 정정·후속 발표는 출처와 기준시각별로 남깁니다.
- 키·비밀번호·개인 위치이력·전체 뉴스본문·대용량 원본·생성된 runs 폴더를 커밋하지 않습니다. 공개 재배포가 불명확한 자료는 조건을 확인한 뒤 공유합니다.
- 팀 협업 방침에 따라 `main`을 기준으로 개인 브랜치 `hyun02063185`에서 자료를 계속 갱신합니다. 일반 작업 절차는 저장소 [AGENTS.md](../../AGENTS.md)를 참고합니다. 사용자와 합의한 자료 업로드는 Loom 설치 없이 진행합니다. 이 예외는 자료·관련 README 업로드에 적용하며 `.loom` 기록은 직접 수정하지 않습니다. 일반 코드 개발 절차의 변경을 의미하지 않습니다.
