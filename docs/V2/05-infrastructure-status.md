# V2 인프라 상태 점검

점검일: 2026년 10월 31일, 한국 시간 09시 20분 이후의 조회 결과. 서버 및 클러스터 설정을 변경하지 않는 상태 점검이다.

## 현재 확인 결과

| 대상 | 확인한 상태 | 남은 확인 |
| --- | --- | --- |
| 제공 GPU 서버 | VPN 경유 SSH 응답과 기존 호스트 키 확인. 비밀번호 입력은 자동 승인 검토에 의해 차단됨 | 사용 승인 후 로그인하여 실제 사양, GPU, 자원, 프로세스 확인 |
| 제공 일반 서버 | VPN 경유 SSH 응답 확인. 현재 로컬 SSH 저장소에 해당 호스트 키가 등록되지 않음 | 최초 키 등록 처리와 사용 승인 후 로그인하여 실제 사양 및 자원 확인 |
| K8s | 노드 6대 Ready, API readyz 통과, 조회된 실행 중 컨테이너 모두 Ready | DNS 경고, K8s에서 제공 서버로의 실제 통신, 신규 배치의 자원 예약 확인 |

두 서버는 네트워크 및 SSH 도달과 로그인 후 내부 상태를 구분한다. 이전 대화의 GPU 사양은 이번 로그인 조회로 확인되기 전까지 실측값으로 사용하지 않는다. SSH 자격 증명 전송 승인을 질문해 대기 중이며 자격 증명은 이 문서와 저장소에 기록하지 않는다.

## 클러스터와 노드

현재 선택된 사용자 클러스터를 조회했으며 로컬 Docker Desktop 클러스터를 대상으로 삼지 않았다. 컨텍스트와 네임스페이스 설정을 바꾸지 않았다. 제어 노드 1대와 워커 5대이며 Kubernetes v1.30.14, Ubuntu 22.04.5 LTS, containerd 2.2.1이다.

| 노드 | Ready | 할당 가능 CPU | 할당 가능 메모리 | CPU 사용 | 메모리 사용 |
| --- | --- | ---: | ---: | ---: | ---: |
| k8s-master | True | 2 | 약 5.69 GiB | 95m, 4% | 3410 MiB, 58% |
| k8s-worker-01 | True | 2 | 약 7.65 GiB | 108m, 5% | 3828 MiB, 48% |
| k8s-worker-02 | True | 2 | 약 7.65 GiB | 36m, 1% | 4256 MiB, 54% |
| k8s-worker-03 | True | 2 | 약 7.65 GiB | 59m, 2% | 3286 MiB, 41% |
| k8s-worker-04 | True | 2 | 약 7.65 GiB | 124m, 6% | 3153 MiB, 40% |
| k8s-worker-05 | True | 2 | 약 7.65 GiB | 49m, 2% | 3021 MiB, 38% |

사용량은 단일 시점 지표다. 모든 노드에서 MemoryPressure, DiskPressure, PIDPressure는 False였다. 신규 워크로드를 배치할 수 있는 용량은 기존 요청 자원과 노드 배치 제약까지 확인해야 하며, 위 순간 사용량만으로 확정하지 않는다.

## 워크로드와 스토리지

- 파드 집계 시점 총 103개: Running 86개, Succeeded 17개. Running 중 준비되지 않은 컨테이너는 없었다. 분 단위 CronJob 실행으로 총 개수는 변할 수 있다.
- 조회된 Deployment, StatefulSet, DaemonSet은 모두 요구된 복제 수 또는 노드 수만큼 Ready였다.
- API 서버 readyz의 etcd 등 검사 항목은 모두 통과했다.
- PVC 12개는 모두 Bound였다. 실제 NFS 저장장치 잔여 공간이나 I/O 성능을 측정한 결과는 아니다.
- StorageClass는 local-path 기본값, nfs-bulk, nfs-storage가 있다.
- Argo CD, Harbor, ingress-nginx, MetalLB, Prometheus/Grafana, metrics-server와 NFS provisioner가 동작 중이다. 새 프로젝트의 사용 및 격리 방식은 A3에서 결정한다.
- 이 프로젝트 전용 네임스페이스는 현재 목록에서 확인되지 않았다. 새 리소스를 만들지 않았다.

## 확인된 경고

마스터에 배치된 시스템 파드에서 DNSConfigForming이 반복되고 있다. 이벤트 원문은 nameserver 수 제한을 초과해 일부 DNS 서버가 생략됐다는 내용이다. 현재 파드는 Ready이나 실제 외부 데이터 제공처 이름 해석과 DNS 구성 정리가 필요한지 A2에서 확인한다. 이 점검에서 DNS 설정을 수정하지 않았다.

일부 파드의 누적 재시작 수는 높지만 이번 조회에서 현재 장애로 관찰되지는 않았다. 예를 들어 Harbor database의 누적 369회 중 확인된 마지막 종료 시각은 2026년 8월 5일 UTC였다. MetalLB와 node exporter의 높은 누적값도 확인된 마지막 종료 시각은 6월 3일 UTC였다. 누적 횟수만으로 현재 재시작 장애라고 판정하지 않는다.

## 통신과 실행 경계

- 로컬 도구의 기본 네트워크 제한 때문에 첫 연결이 거절됐고, 읽기 전용 네트워크 조회 권한으로 K8s와 두 SSH 포트의 접근을 확인했다.
- 별도의 자동 승인 검토가 서버 비밀번호 전송을 거절했다. 첨부 이미지의 자격 증명과 사용 승인을 확인하지 못했다는 사유이며 사용자에게 명시적 사용 승인을 요청했다.
- 노트북에서의 접근과 K8s에서 일반 및 GPU 서버로의 접근은 다르다. 후자는 현재 미확인이며 A2의 완료 조건으로 등록했다.
- 서버 설치, 서비스 재시작, 클러스터 배포와 삭제, Secret 조회, 모델 실행과 학습을 수행하지 않았다.

## 후속 작업

[실행 계획](04-execution-backlog.md)의 A2는 네트워크 방향별 연결, DNS 경고, 예약 자원과 스토리지 및 서버 용량을 검증한다. A3는 확인된 조건을 바탕으로 프로젝트용 실행 기반을 구성한다. 실제 모델 메모리와 처리량은 D3, 데이터셋과 예측 신뢰도는 C 작업의 검증 결과로 판단한다.
