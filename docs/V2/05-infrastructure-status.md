## 워크로드와 스토리지

- 파드 집계 시점 총 103개: Running 86개, Succeeded 17개. Running 중 준비되지 않은 컨테이너는 없었다. 분 단위 CronJob 실행으로 총 개수는 변할 수 있다.
- 조회된 Deployment, StatefulSet, DaemonSet은 모두 요구된 복제 수 또는 노드 수만큼 Ready였다.
- API 서버 readyz의 etcd 등 검사 항목은 모두 통과했다.
- PVC 12개는 모두 Bound였다. 실제 NFS 저장장치 잔여 공간이나 I/O 성능을 측정한 결과는 아니다.
- StorageClass는 local-path 기본값, nfs-bulk, nfs-storage가 있다.
- Argo CD, Harbor, ingress-nginx, MetalLB, Prometheus/Grafana, metrics-server와 NFS provisioner가 동작 중이다. 새 프로젝트의 사용 및 격리 방식은 A3에서 결정한다.
- 이 프로젝트 전용 네임스페이스는 현재 목록에서 확인되지 않았다. 새 리소스를 만들지 않았다.

## 확인된 경고

마스터에 배치된 시스템 파드에서 DNSConfigForming이 반복되고 있다. 이벤트 원문은 nameserver 수 제한을 초과해 일부 DNS 서버가 생략됐다는 내용이다. 현재 파드는 Ready이나 실제 외부 데이터 제공처 이름 해석과 DNS 구성 정리가 필요한지 A2에서 확인한다. 이 점검에서 DNS 설정을 수정하지 않았다.

일부 파드의 누적 재시작 수는 높지만 이번 조회에서 현재 장애로 관찰되지는 않았다. 예를 들어 Harbor database의 누적 369회 중 확인된 마지막 종료 시각은 2026년 8월 5일 UTC였다. MetalLB와 node exporter의 높은 누적값도 확인된 마지막 종료 시각은 6월 3일 UTC였다. 누적 횟수만으로 현재 재시작 장애라고 판정하지 않는다.

## 통신과 실행 경계

- 로컬 도구의 기본 네트워크 제한 때문에 첫 연결이 거절됐고, 읽기 전용 네트워크 조회 권한으로 K8s와 두 SSH 포트의 접근을 확인했다.
- 처음에는 자동 승인 검토가 자격 증명 사용 승인을 확인하지 못해 전송을 차단했다. 사용자의 명시적인 두 서버 로그인 승인 후 접속과 내부 조회를 완료했다. 현재 승인 대기 항목은 없다.
- GPU 서버는 기존 호스트 키와 일치했다. 일반 서버는 첫 연결의 호스트 키를 로컬 임시 known_hosts에 등록하고, 이후 엄격한 키 검사를 사용했다. 로그인 후 두 서버의 호스트명이 제공 자료와 일치함을 확인했다.
- 두 서버 간 TCP 22 연결을 양방향으로 확인했다. 이는 향후 API 포트의 개방 또는 K8s발 연결을 보장하지 않는다.
- 노트북에서의 접근과 K8s에서 일반 및 GPU 서버로의 접근은 다르다. 후자는 현재 미확인이며 A2의 완료 조건으로 등록했다.
- 서버 설치, 서비스 재시작, 클러스터 배포와 삭제, Secret 조회, 모델 실행과 학습을 수행하지 않았다.
- 두 SSH 세션은 점검 후 종료했다.

## 후속 작업

[실행 계획](04-execution-backlog.md)의 A2는 네트워크 방향별 연결, GPU 서버의 실패 서비스 2개, DNS 경고, 예약 자원과 스토리지 및 서버 용량을 검증한다. 실측 결과와 남은 확인 항목은 A2 및 D3의 Loom 메모에도 연결했다. A3는 확인된 조건을 바탕으로 프로젝트용 실행 기반을 구성한다. 실제 모델 메모리와 처리량은 D3, 데이터셋과 예측 신뢰도는 C 작업의 검증 결과로 판단한다.
