## 유지한 표현

흰 배경의 옅은 파란 점·십자 무늬, 연노란 그룹 영역, 보라색 사각형과 DB 원통, 빨간 긴급 경로, 민트색 GPU API 상자, 얇은 직각 연결선을 유지했다. 입력 영역은 위쪽, 일반 서버는 가운데, 클라이언트와 GPU 서버는 아래쪽에 배치했다.

## 반영한 변경

- K8s 상시 수집을 시연 자료 입력으로 수정하고 수집 보류 상태를 표시했다.
- DB의 기본 지침과 벡터 저장을 명시하고 분석 큐에서 저장·웹 자료를 검색하도록 표현했다.
- 공식 경보는 긴급 큐에서 대상 확인과 원문 보존을 거쳐 AI 대기 없이 전달한다.
- 실제 예측 미연결 상태의 XGBoost는 점선으로만 표시하고 현재의 공식 근거·고정 규칙 경로를 유지했다.
- 개인별 정책에 **1 경고 · 2 대피 · 3 위급**, DB 지침과 고정 규칙, 입력 변경·만료에 따른 재평가를 반영했다.
- Qwen 자료 정리와 임베딩 벡터 생성을 구분했다. 분석 워커가 두 모델을 호출하고 정리 결과를 사건 자료로 전달한다.
- FCM 모의 전송, 클라이언트의 변경 조회·화면 갱신과 기기 TTS, 단말 연동 검증 중 상태를 표시했다.

이 그림은 현재 MVP의 시연 구조다. 일반 서버의 최신 설치 API·사설 HTTPS 배포는 [배포 기록](mobile-server-deployment.md)을 따른다. 실제 예측과 Firebase 단말 수신을 완료로 표시하지 않았다. 전체 구조의 비교 근거는 [기존 비교 문서](presentation-architecture.md)에 있다.
