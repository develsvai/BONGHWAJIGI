# 봉화지기 기획 기준

갱신: 2026-10-31 23:06 (체크리스트 결정 반영) · 적용 재난: 산불

봉화지기 기획의 기준 문서다. 절마다 **정해진 것**과 **정할 것**으로 나눈다. 정할 것에는 현재 안을 함께 적고, 결정되면 정해진 것으로 옮긴다.

| 표기 | 뜻 |
| --- | --- |
| (안) | 결정 전 제안 |
| (승인 필요) | 행동요령에 없는 서비스 판단 |
| (해외 지침) | 미국 Ready, Set, Go!·호주 CFA의 고립 시 지침 |
| (후보) | 채택 전 입력 항목 |

## 1. 서비스

### 정해진 것

- 서비스명은 봉화지기다. 화면 상단에는 '봉화 지기'로 쓴다.
- 위험이 사용자에게 닿기 전에 준비하고 대응할 시간을 확보해 주는 재난 대응 비서다. 같은 재난이라도 사람마다 움직일 때와 할 일을 다르게 안내한다.
- 적용 재난은 산불이다.
- 처리 흐름: 공식 경보·관측·뉴스 수집 → 사건 통합 → 내 위치·관심 장소와의 관련성 확인 → 위험 평가 → 개인별 대응 정책 적용 → 알림·안내 갱신.
- 공식 긴급 경보는 별도 경로로 원문·출처·발령 시각을 먼저 전달한다. 추가 분석을 기다리지 않고, 낮은 예측값으로 공식 지침을 숨기거나 낮추지 않는다.
- 개인별 대응은 사람이 정한 규칙을 서버가 적용한다. AI(Qwen3-4B)는 문서에서 사실을 뽑고 선택된 안내를 설명할 뿐 행동을 정하지 않는다.
- 공식 경보 상태와 개인 대응 단계는 따로 다룬다.
- 예측할 수 없으면 '예측 불가'로 두고 0%로 표시하지 않는다. 확인하지 못한 위치·상태로 안전하다고 단정하지 않는다. 경보 해제는 안전과 같지 않다.
- 영향 확률 모델(XGBoost 후보)을 MVP에 포함한다.

### 정할 것

- 주 대상 사용자 범위. 정책은 고령, 장애, 동반 보호 대상을 포함해 설계한다(안).
- 영향 확률 모델의 산불 예측 목표와 입력

## 2. 화면

### 2.0 공통

#### 정해진 것

- 화면은 홈, 긴급 대응, 프로필, 재난별 기본 수칙 4개다.
- 지도와 대피 경로는 2D다.
- 화면 이동

  | 출발 | 동작 | 도착 |
  | --- | --- | --- |
  | 홈 | 상단 '프로필' | 프로필 |
  | 프로필 | 뒤로 | 홈 |
  | 재난 알림 | 열기 | 긴급 대응 |
  | 홈 | 활성 재난 안내 선택 | 긴급 대응 |
  | 긴급 대응 | 하단 [기본 수칙] | 재난별 기본 수칙 |
  | 재난별 기본 수칙 | 뒤로 | 긴급 대응 |

- 홈의 '주변 재난 사항' 항목은 눌러도 다른 화면으로 가지 않는다.
- 단계·이유·행동·대화 문구는 서버가 주고 앱은 표시한다. 앱이 위험을 계산하지 않는다.
- 상태 표시
  - 위치가 없거나 오래되면 '현재 위치 확인 필요'로 표시하고, 현재 위치 기반 정보라고 쓰지 않는다.
  - 목록이 비면 '조건에 맞는 정보 없음'으로 쓰고 안전하다는 문구로 바꾸지 않는다.
  - 일부만 받았거나 오래된 자료는 마지막 갱신 시각을 함께 표시한다.
  - 시연 데이터는 시연임을 표시한다.
  - 통신 실패를 안전·해제·신고 완료로 표시하지 않는다.

### 2.1 홈

#### 정해진 것

위에서 아래로 다음 순서다.

| 순서 | 영역 | 규칙 |
| --- | --- | --- |
| 1 | 상단 | '봉화 지기'와 '프로필' 진입 문구 |
| 2 | 지도 | 별도 제목 없이 2D 지도와 내 위치로 시작한다. 위치 아이콘과 지역명은 지도 아래에 둔다. 조회 반경 설정과 별도 GPS 버튼은 두지 않는다. |
| 3 | 오늘의 행동요령 | 제목 아래 카드형 안내. 일반 수칙을 지역 특화 수칙처럼 표시하지 않는다. 자료가 없으면 수칙을 만들어 채우지 않는다. |
| 4 | 나의 사전준비 | 준비 카드 최대 2개. 오늘의 행동요령 카드와 아이콘 배치·크기·테두리·배경·여백·글자 스타일이 같다. 사용자가 입력한 프로필과 서버가 확인한 재난 상황으로 고르고, 입력하지 않은 상태나 보조기구 종류를 추정하지 않는다. |
| 5 | 주변 재난 사항 | 조회 시점 기준 최근 3개월 이내, 최신순 최대 3건. 진행 중·종료 모두 같은 규칙이고, 3건보다 적으면 있는 것만 보인다. 행마다 재난명·진행 상태·시각·간단한 상황을 쓴다. 종료된 재난 제목에는 '발생'을 넣지 않는다. 상세 화면 이동 버튼은 없다. 시각과 상태는 받은 데이터 그대로 쓴다. |

- 세 영역 제목(오늘의 행동요령, 나의 사전준비, 주변 재난 사항)은 같은 크기·서체다.
- '주변 재난 사항' 제목과 목록 사이 간격은 '오늘의 행동요령' 제목과 카드 사이 간격과 같다.
- 오늘의 행동요령은 서버가 공식 수칙의 예방·대비 항목을 날짜별로 돌려 보낸다.
- '주변'은 반경으로 정한다.
- 표시할 자료가 없으면 '조건에 맞는 정보 없음'과 조회 조건 한 줄(예: 최근 3개월 · 반경 ○km)을 쓴다.
- 나의 사전준비는 서버가 단계별 할 일(3절)과 유형별 행동(5절)에서 고른다.
- 진행 중과 종료는 텍스트 태그로 나누고 진행 중만 강조색을 쓴다.
- 위치 권한이 없으면 주요 생활 장소 기준으로 조회하고 '현재 위치 확인 필요 · ○○ 기준'으로 표시한다.

#### 정할 것

- '주변' 반경 값(km)
- 오늘의 행동요령 문구

### 2.2 긴급 대응

#### 정해진 것

본문은 스크롤하고 하단 버튼은 고정한다. 위에서 아래로 다음 순서다.

| 순서 | 영역 | 규칙 |
| --- | --- | --- |
| 1 | 경보 | 삼각형 느낌표 픽토그램과 공식 경보 제목을 가운데 정렬한다. 별도 등급 문구(예: '심각')는 두지 않는다. 제목은 공식 경보 제목을 쓰고, 공식 대피 지시일 때만 '대피 명령'이라고 쓴다. |
| 2 | 재난 영향 지역 | 2D 지도. 영향 지역은 지도 중앙의 반투명 붉은 면, 사용자 위치는 별도 표시로 보여 준다. 줄무늬나 '지도 샘플' 문구는 넣지 않는다. 출처가 없는 영역을 영향 지역처럼 그리지 않는다. 대피로 경로도 이 지도에 겹쳐 그린다. |
| 3 | 실시간 음성 대화 | 중앙 파형과 서버 발화 한 개. 새 발화가 오면 바꿔 끼우고 대화 이력은 쌓지 않는다. 사용자 발화, 'AI 대화 안내' 제목, AI 캐릭터, 제목 옆 파형 아이콘은 넣지 않는다. 파형은 실제 녹음·재생 상태를 따르고, 음성 기능이 꺼져 있으면 움직이지 않는다. |
| 4 | 내 현재 상태 | 상태 태그. 처음에는 프로필에서, 이후에는 대화로 확인한 상태로 채운다. '혼자 있음'은 지금 확인된 경우에만 붙인다. 위치 태그는 유효한 위치가 있을 때만 붙인다. |
| 5 | 맞춤 행동요령 | 제목 바로 아래 번호별 행동(1, 2, 3…)을 텍스트로 쓴다. 도입 문구와 설명 박스는 넣지 않는다. |
| 6 | 하단 고정 버튼 | 왼쪽 [기본 수칙]은 재난별 기본 수칙, 가운데 [대피로]는 2번 지도에 2D 경로 표시, 오른쪽 [119 신고]는 6절 규칙을 따른다. |

- '재난 영향 지역', '실시간 음성 대화', '내 현재 상태', '맞춤 행동요령' 제목은 홈 '오늘의 행동요령'과 같은 스타일이다. 영역 사이 간격은 홈 '주변 재난 사항' 위 간격과 같다.
- 공식 경보를 먼저 띄우고 개인 안내와 지도는 따로 불러온다. 개인 안내가 아직 없으면 공식 경보, 기본 수칙, 119 신고로 화면을 구성하고, AI를 기다리는 전용 화면은 두지 않는다.
- 경로가 달라지거나 유효 시간이 지나면 지도에서 지우고 새 안내를 기다린다.
- 하단 버튼은 3등분 같은 너비, 간격 8px이고 [119 신고]는 붉은 테두리다.
- 서버 발화는 대피 단계부터 자동 재생한다. 마이크는 파형을 탭해 켜고 끄며, 끼어들기는 두지 않는다.
- 맞춤 행동요령 읽어 주기는 두지 않고 스크린리더 라벨로 대신한다.
- 지도는 확대·이동만 허용하고 회전·기울기는 끈다.
- 사용자 유형별 추가 UI(조력자 연락 버튼, '청각장애 알림' 화면)는 시연 범위 밖이다.

#### 정할 것

- 개인 대응 단계 표시 위치와 모양(UI 확인 후)
- [대피로] 버튼 유지 여부(제거 의견 있음)
- 음성 대화 상태별 문구
- 프로필이 비었거나 상태를 확인하지 못했을 때 처리
- 산불 시연 문구: 경보 제목, 발화 예시, 맞춤 행동요령(9절)

### 2.3 프로필

#### 정해진 것

- 재난 전에 자기 상태를 미리 입력하는 곳이다. 상단 제목은 '프로필'이고, 왼쪽 뒤로 버튼은 홈으로 간다.
- 상단 이름·제목·첫 정보 박스 사이 간격은 좁게 잡고, 선택되지 않은 태그 글자도 읽기 쉽게 표시한다.
- 입력은 기본 정보, 이동과 의사소통, 추가 정보 세 묶음으로 나눈다.
- 프로필은 긴급 대응 '내 현재 상태'가 처음 참고하는 정보다. 재난 중 확인되지 않은 상태를 현재 사실로 표시하지 않는다.
- '지금 혼자 있음'은 프로필에 저장하지 않는다.
- 묶음별 항목은 아래와 같고 모두 선택 입력이다.

  | 묶음 | 항목 |
  | --- | --- |
  | 기본 정보 | 이름 또는 호칭, 연령대 |
  | 이동과 의사소통 | 이동 능력(독립 보행·보행 보조·휠체어·타인 도움 필요), 계단 이용(가능·어려움·불가능), 차량 이용, 선호 안내(음성·문자·둘 다), 시각 지원, 청각 지원, 함께 대피할 보호 대상(영유아·돌봄 대상자·반려동물) |
  | 추가 정보 | 긴급 연락처, 조력자 지정 여부, 주요 생활 장소 |

- 민감 정보는 기기에 저장하고 서버에는 판정에 쓰는 범주값만 보낸다. 처음 입력할 때 동의 화면을 거치고, 프로필에 전체 삭제 버튼을 둔다.

#### 정할 것

- 7절 우선순위 2 입력(가축, 쉬운 안내 필요 등)을 프로필에 넣을지

### 2.4 재난별 기본 수칙

#### 정해진 것

- 국가 등 공식 기관이 제공하는 해당 재난의 기본 행동수칙만 보여 준다. 긴급 대응의 맞춤 행동요령과 섞지 않는다.
- 긴급 대응 [기본 수칙]으로 열고, 그 재난 유형의 수칙을 보여 준다. 왼쪽 뒤로 버튼은 긴급 대응으로 간다.
- 순서: 제목 '산불 행동수칙' → '산불 대비 기본수칙' → 번호별 수칙 → '이런 행동과 장소는 피하세요'
- 뒤로 버튼과 제목의 간격·규격은 프로필과 같다. 수칙 설명과 피해야 할 장소 글씨는 검은색이다.
- 자료가 없으면 미확보로 표시하고 내용을 만들어 채우지 않는다. 번역이 없으면 원문 언어로 보여 주고 그 사실을 표시한다.
- 산불 수칙은 국민재난안전포털 산불 국민행동요령 원문을 쓴다.
- 화면 하단에 출처와 확인일을 한 줄로 표시한다.

## 3. 개인별 대응 단계

2026-10-31 사용자 확정: **1단계 경고(`prepare`) → 2단계 대피(`act`) → 3단계 위급(`request_assistance`)**. 평소는 단계 밖, 확인 중은 `unknown`, 대피 후 안내는 `information`이다. 4단계로 나누는 안은 채택하지 않는다. 현재 실행 기준은 [확정 정책](../V2/delivery/response-policy.md)이며 아래 미결정 초안과 충돌하면 이 확정을 우선한다.

### 정해진 것

- 공식 등급을 따르지 않고 서비스 규칙으로 정한다.
- 평소는 단계가 아니다. 산불이 나와 관련될 때부터 단계가 시작된다.
- 단계 구분과 명칭은 기획 담당이 정한다.
- 단계는 ①②③ 3단계다.
- 명칭은 ① 경고, ② 대피, ③ 위급이다. 간결하게 짓고 단계끼리 같은 낱말을 쓰지 않으며, 공식 용어와 겹쳐도 된다.

### 정할 것

- **단계 원칙(안)**
  - 한 단계는 사용자 행동이 바뀌는 지점 하나다.
  - 산불이 얼마나 가까운지(환경 구간)와 지금 할 일(개인 단계)을 따로 판단한다.
  - 사용자 특성은 진입 시점, 행동, 전달 방식을 바꾼다.
  - 단계는 즉시 올리고 천천히 내린다.
  - 가장 안전한 건 일찍 떠나는 것이다. ③은 마지막 수단이고, 앱의 목표는 사람들이 ③까지 가지 않게 하는 것이다.

## 4. 단계 판정 규칙

## 6. 119 신고

### 정해진 것

- 119 앞에 앱 안 확인 화면이나 질문을 두지 않는다.
- 긴급 대응 하단의 [119 신고] 버튼 하나로 연결한다. 시트를 띄우지 않고 문자 버튼과 전화 버튼으로 나누지 않는다. ③에서도 같다.
- 문자 초안은 앱(휴대폰)에서 만든다. 서버 응답을 기다리지 않고, 서버나 통신에 문제가 있어도 119 연결을 막지 않는다.
- 마지막 전송과 통화는 사용자가 OS의 문자·전화 화면에서 누른다.
- 문자 화면 열기, 전송, 통화, 접수를 하나의 성공 표시로 합치지 않는다. 앱은 신고 접수 완료를 표시하지 않는다.
- 시연에서는 실제 119로 보내거나 걸지 않는다.

### 정할 것

- 버튼이 여는 화면(문자 작성 또는 전화)과 유형별 기본 채널. 청각·언어장애는 문자, 시각장애와 고령자는 전화(안).
- 문자에 넣을 프로필 정보와 동의 방식. 장애·건강 정보는 프로필에서 미리 동의한 항목만 넣는다(안).
- 문자 초안 틀(안): 위치(주소·좌표·측정 시각)를 맨 앞에 두고 거동 상태, 인원, 상황을 잇는다. 확인된 값만 넣고 모르는 값은 묻지 않고 뺀다. 위치가 오래됐으면 측정 시각을 붙인다.

- 개인정보 원칙(안)
  - 모두 선택 입력이다. 모르면 unknown이고 '없음'으로 보지 않는다.
  - 진단명이 아니라 필요한 지원으로 받는다. 예: '천식'이 아니라 '연기에 특히 취약'.
  - 나이는 연령대 구간만 받는다.
  - 조력자·긴급 연락처는 기기에만 두고 서버에는 지정 여부만 보낸다.

## 8. 서버·API 연결

### 정해진 것

- `personal_response.level` 값의 의미

  | 값 | 의미 |
  | --- | --- |
  | `attention` | 스키마에 남기고 보내지 않음 |
  | `prepare` | 경고 |
  | `act` | 대피 |
  | `request_assistance` | 위급 |
  | `information` | 진화 후·해제 안내 |
  | `unknown` | 확인 중 |

- 추가 필드: 프로필 `age_band`, `vehicle_access`, `helper_registered`, 현재 상태 `location_type`, `observed_hazard`, `evacuation_status`, `injured`
- 서버 문자 초안 API(`createSupportDraft`)는 쓰지 않고 계약에 미사용으로 표기한다.
- 홈 '나의 사전준비' 카드는 서버가 고른다.

### 정할 것

- 경로 막힘과 모름 표현: `route_availability.reason_code`로 나눈다(예: `ROUTE_BLOCKED`, `ROUTE_UNCONFIRMED`)(안). 전용 필드 `route_status`를 둘 수도 있다.

API 상세 초안은 [앱 API 계약](../V2/delivery/app-api-contract.md), [화면별 인계서](../V2/delivery/api-handoff.md), [API별 사용법](../V2/delivery/api-reference.md)과 앱 저장소의 [화면·API 매칭 리스트](https://github.com/duswls98952/BONGHWAJIGI_APP/blob/main/docs/HeoNey/모바일_화면_API_매칭_리스트.md)에 있다.

## 9. 시연

### 정해진 것

- 산불로 시연한다.
- 한 지역의 과거 산불 사례를 당시 공개된 정보만 시간순으로 재생한다. 나중에 알려진 피해 정보를 앞 시점에 넣지 않는다.
- 가까이 있지만 이동·지원·전달 설정이 다른 사용자를 함께 등록해 안내 차이를 보여 준다.
- 공식 긴급 지침이 오면 AI를 기다리지 않고 원문부터 전달하는 모습을 보여 준다.
- 통제·해제나 위치 변경에 따라 안내가 갱신되는 모습을 보여 준다.
- 시연 데이터는 화면에 시연임을 표시하고, 실제 119로 연락하지 않는다.
- 사례는 2025년 3월 의성 산불 중 한 마을의 반나절 구간이다.

### 정할 것

- 시연 사용자와 장면(안): A(독립 성인, 차량 있음)와 B(고령자, 보행 보조, 지금 혼자 있음, 차량 없음)를 같은 마을 H2에 두면 A는 ①, B는 ②를 받는다. 이어서 대피 명령이 오면 둘 다 원문부터 받는다. B는 이동 능력(보행 보조) 입력만으로 여유 필요가 된다.
- H1~H3 거리 값(백엔드가 사례에 맞춰 제안)
- 시연 문구: 경보 제목, 발화 예시, 맞춤 행동요령, 기본 수칙
