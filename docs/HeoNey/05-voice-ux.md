# 05. 공유 대화의 음성 대피 화면

[문서 안내](README.md) · 근거: [M053–M056](archive/conversation-07.md#m053)

이 문서는 **공유 대화의 마지막 버전**을 기록한다. 이후 별도로 작성된 [5개 화면 기획서](봉화지기_모바일_화면_기획서.md)는 더 최근의 요구를 담고 있으므로 실제 화면 설계에는 그 문서의 최신 수정사항을 우선 적용한다.

## 마지막 대화에서 요청한 화면 비율

| 영역 | 사용자 요청 | 답변의 표현 |
| --- | --- | --- |
| 상단 약 2/3 | Siri처럼 움직이는 원형 모형, 중앙의 AI 말, 그 아래 사용자 말 박스 | 음성 대화의 주 영역 |
| 하단 약 1/3 | 대화로 계속 바뀌는 현재 내 상태 | 상태 태그와 다음 행동 버튼 |

사용자는 채팅 앱처럼 대화 말풍선을 계속 쌓는 화면을 원하지 않았다. 최신 발화가 중심에 보이고 지난 발화는 위로 밀려나는 형태를 설명했다. 답변은 원형 모션의 말하기·듣기·응답 준비·일시 중지 상태와, 이전 대화가 필요할 때 스크롤하는 방식을 제안했다.

마지막 답변에 들어 있는 [HTML/CSS 시안 원문](archive/conversation-07.md#m056)은 배치와 원형 애니메이션을 보여주는 정적 시안이다. 실제 음성 인식·119 전화·경로 기능이 연결된 화면은 아니며 색상도 임시였다.

## 자동 음성 인식과 끼어들기

사용자는 별도의 “말씀해 주세요” 버튼 없이 화면에 들어온 순간 음성 인식이 시작되고, AI가 말하는 중에도 사용자의 말을 듣는 경험을 원했다. 답변은 발화 중 끼어들기(barge-in)를 위해 실시간 입력, 사용자 발화 감지, AI 음성 출력 중단, 스피커 소리의 재인식 방지가 필요하다고 설명했다.

마이크 버튼을 없애더라도 작동 상태를 알리고 끌 수단은 제공하자는 것은 답변의 제안이다. 최초 마이크 권한, 권한 거부 시 동작, 실제 지원 단말과 지연은 대화에서 확정하지 않았다.

## 프로필과 현재 상태

대화 시작 전에는 저장된 프로필을 현재 상태의 기본값으로 보여주고, 새 발화를 듣고 달라진 조건을 반영한다. 예를 들어 “독립 보행 가능”을 저장한 사람이 “지금 다리가 아파 오래 걷기 힘들다”고 하면 이전 태그를 그대로 두지 않고 “장거리 보행 어려움”, “계단 이용 확인 필요”처럼 바꾼다.

“걷기 힘들다”를 곧바로 “전혀 걸을 수 없다”고 단정하지 않는 짧은 재확인, 재난 중 상태를 평상시 프로필과 분리하는 방식은 답변의 보완 제안이다.

## 대화 도중 다음 행동

사용자는 AI가 대화 종료를 판단하지 못해도 “대피로 알려줘” 같은 직접 요청으로 다음 화면에 갈 수 있기를 원했다. 답변은 언제나 누를 수 있는 “대피 방법 보기”와 “119 전화” 버튼을 제안했다. 이동 가능하고 경로가 확인되면 경로 안내, 혼자 이동하기 어렵다면 긴급 지원, 경로 정보를 확인하지 못했다면 공식 지침과 도움 요청으로 나뉜다.

이 공유 대화의 시안에는 **사용자 발화 박스와 원형 애니메이션**이 있었지만, 나중에 작성된 5개 화면 기획서에서는 사용자 발화를 화면에 표시하지 않고 구형 AI 캐릭터를 제거하며 중앙 파형을 유지한다. 두 버전의 차이는 [결정·변경 기록](07-decisions-and-open-questions.md)에 따로 적었다.
