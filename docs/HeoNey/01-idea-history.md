# 01. 아이디어 탐색 전체 이력

[문서 안내](README.md)

공유 대화는 처음부터 재난 앱으로 시작하지 않았다. 누구나 공감할 문제, 추천 대상의 새로움, 실제 사람과의 연결, 정보보호, 지원받은 GPU의 활용을 탐색하다가 개인별 재난 대응으로 좁혀졌다. 아래 초기 후보들은 탐색 기록이며 현재 앱에 모두 구현할 기능이 아니다.

## 관광 안내와 지하철 로드뷰

근거: [M001–M006](archive/conversation-01.md#m001).

사용자는 한국인이 방한 외국인을 안내하는 서비스의 존재를 물었다. 답변은 현지인 매칭, 로컬 체험, 전문 가이드의 세 범주로 나누고 local/seoul, HanBuddy, BeKo, 에어비앤비 체험, 서울시 도보해설관광을 비교했다. 친구로 만나는 방식과 유료 관광 안내의 운영 조건을 구분해야 한다는 의견도 포함됐다.

이어 지하철 로드뷰가 있는지 물었고, 실제 의도는 **환승할 때 길을 찾기 어려우므로 실제 사진으로 이동 과정을 안내하는 것**이라고 구체화했다. 네이버 실내 거리뷰, S-MAP, 카카오지하철, 또타지하철, 서울동행맵, 카메라 기반 AR 내비게이션이 비교 대상으로 등장했다. 단순 역사 둘러보기와 목적지까지 연결된 환승 안내를 구분했다.

제안된 단계는 사진 순서 안내, 360도 사진과 화살표, 카메라로 현재 위치를 알아내는 안내다. 앞의 두 방식은 AI 없이도 가능하며, AI 역할은 위치·표지판 인식과 이용자에게 덜 복잡한 경로 추천에서 찾았다. 해커톤은 복잡한 환승역 한 곳으로 좁히고 정확한 동선·사진·사용 권한을 먼저 확보하자는 제안이었다.

## 추천과 정보보호의 관점을 바꾸기

근거: [M007–M008](archive/conversation-01.md#m007).

사용자는 해커톤의 두 주제인 AI 기반 추천과 AI 기반 정보보호 안에서 관점 자체가 참신한 서비스를 원했다.

| 분야 | 제안된 아이디어 | AI의 역할 또는 주의점 |
| --- | --- | --- |
| 추천 | 가장 덜 헤매는 길 | 표지판·갈림길·통로 복잡도 분석; 실패 확률에는 실제 데이터 필요 |
| 추천 | 내가 해야 하는 질문 | 문서의 빠진 조건을 찾아 계약·상담 전에 확인할 질문 제시 |
| 추천 | 아무것도 사지 않기 | 이미 가진 물건으로 대체 가능한지 분석 |
| 추천 | 나를 필요로 하는 곳 | 개인 역량·시간과 실제 지역 도움 요청 연결 |
| 정보보호 | 조합 정보 노출 분석 | 여러 사진·게시물이 합쳐져 드러나는 위치·생활 패턴 위험 설명 |
| 정보보호 | 필요한 만큼만 공개 | 제출 목적에 따라 정보의 보존·가림 범위 추천 |
| 정보보호 | 사진 속 타인의 정보 보호 | 얼굴·명찰·사원증·차량번호 등 제3자 식별정보 탐지 |
| 정보보호 | 정보의 유통기한 | 1회 열람·시간제한 공유 정책 추천; 실제 차단은 권한 관리로 구현 |

기존 사례로 위치 노출 분석, 자동 모자이크, 이미지 위치추론 연구 등이 언급됐다. 참신성과 구현 난이도 표는 당시 답변의 기획 평가이며 실증된 점수가 아니다.

## 취업 공백 청년: 활동 추천에서 사람 추천으로

근거: [M009–M014](archive/conversation-02.md#m009).

사용자의 출발 문장은 “당신은 가치가 있습니다”였다. 장기간 취업하지 못해 자신감을 잃은 청년을 위해 세 후보가 제안됐다.

| 후보 | 내용 |
| --- | --- |
| 당신을 필요로 하는 순간 | 지금 가능한 작은 사회적 기여 기회 추천 |
| 세상으로 돌아가는 가장 작은 문 | 감당할 수 있는 부담에 맞춰 사회적 연결을 단계적으로 추천 |
| 공백이 아니라, 내 이야기 | 공백기 경험을 재발견하고 다음 경험으로 연결 |

사용자는 세 번째를 선택했다. 초기 답변은 경험 회고 → 삶의 기록 재구성 → 다음 활동 추천을 제안했으나, 사용자는 AI의 활동 추천이 형식적이라고 지적하고 **추천이나 조언을 해줄 수 있는 사람을 AI가 찾는 방향**으로 바꿨다.

수정된 흐름은 이야기 이해 → 실제 경험이 겹치는 사람 탐색 → 연결 이유 설명 → 선택적인 대화 시작 질문 지원이다. 장기 취업 준비 경험자, 다른 분야로 진로를 바꾼 사람, 비슷한 고민을 하는 또래가 가상 후보로 등장했다. 높은 성취를 가진 멘토만 찾기보다 살아온 경험을 연결한다는 의미였다. 매칭 동의와 검증된 참여자, 활동하지 않을 자유, 가치와 생산성을 동일시하지 않기 등이 답변의 보완 제안이었다.

## 아동 서비스와 개인정보 보호

근거: [M015–M020](archive/conversation-02.md#m015), [보호 통합 이후](archive/conversation-03.md#m017).

아동 대상 탐색에서는 다음 여섯 가지가 나왔다.

1. 모두가 참여할 수 있도록 놀이 규칙을 바꾸는 추천.
2. 주변 물건을 활용한 놀이 추천.
3. 누구에게 어떻게 도움을 요청할지 안내.
4. 보호자가 아이 사진을 공유할 때 아이의 의사와 개인정보를 존중하는 도구.
5. 게임·채팅 화면에서 드러나는 개인정보 탐지.
6. 그림·창작물에서 작품과 이름·학교 등 개인정보를 분리.

사용자는 **5번과 6번을 결합하고 부모를 마케팅 대상으로 삼는 방향**을 제시했다. 위치추적 앱처럼 자녀의 개인정보를 지키기 위해 설치하는 서비스라는 설명이었다. 답변은 게임 캡처, 작품, 일상 사진의 신원·학교·위치·연락처를 게시 전에 탐지하고 수정하는 흐름으로 정리했다.

MVP 제안은 이미지 업로드 → 위험 부분 표시 → 가릴 항목 선택 → 안전한 이미지 저장이다. 공유 메뉴 연동과 권한을 받은 사진첩 검사는 검토 대상으로 두되, 설치만으로 다른 모든 앱의 전송을 감지·차단할 수 있다고 약속하지 않았다. 부모에게 모든 활동을 보고하는 감시 기능과는 구분했다.

사용자가 NVIDIA L4 지원 사실을 알리자 이미지보다 무거운 멀티모달 분석으로 확대했다.

| 후보 | 내용 | 당시 제안 범위 |
| --- | --- | --- |
| A. 멀티모달 개인정보 보호 | 짧은 영상의 프레임·글자·인물·음성에서 노출 구간 탐지 후 편집 | 중심 후보 |
| B. 조합 정보 노출 방지 | 여러 게시물과 새 콘텐츠를 함께 보고 추론되는 개인정보 위험 분석 | A와 통합 제안 |
| C. 실시간 정보 노출 예방 | 방송 중 공개되는 정보를 감지·차단 | 향후 확장 |

PaddleOCR, 객체 탐지, Qwen2.5-VL 3B/7B, Whisper, OpenCV·FFmpeg가 이 후보의 기술 예시였다. 이 이름들이 재난 앱의 채택 모델로 결정된 것은 아니다.

## 외국인 QR 지하철 안내와 참여형 데이터

근거: [M021–M024](archive/conversation-03.md#m021).

사용자는 지하철 QR을 찍어 바로 길찾기를 이용하고, 출발지·도착지를 입력하면 경로와 어려운 환승 구간의 사진을 보는 서비스를 제안했다. 답변은 QR 기반 웹 진입, QR 역을 출발지로 자동 지정, 다국어 목적지 검색, 환승 사진과 화살표, 도착역 출구 안내로 구체화했다. “Scan. Find. Transfer.”라는 문구도 등장했다.

AI는 단순 최단 경로보다 외국인 초행자가 따라가기 쉬운 경로를 추천하고, 표지판을 인식·번역하며 길안내 문장을 만드는 역할로 제안됐다. 외국인용 공식 지하철 앱이 이미 존재한다는 당시 답변을 전제로, 설치 부담과 환승 현장의 세부 안내에 차별점을 두었다.

사용자는 처음에는 운영진이 사진을 제공하고 이후에는 외국인이 직접 헷갈린 지점의 사진을 올리는 구조를 추가했다. 답변이 제안한 흐름은 다음과 같다.

1. 운영진이 실제 사진과 동선을 등록한다.
2. 이용자가 특정 경로·단계에서 사진, 혼란 이유, 변경된 표지판을 제보한다.
3. AI가 표지판·출구번호 추출, 사진 비교, 다국어 제보 분류, 같은 지점 묶기를 한다.
4. 운영진이 검토한 뒤 안내에 반영한다.

사진 즉시 공개 대신 검토 후 반영은 답변의 제안이다. 외국인의 혼동은 국적뿐 아니라 언어·이용 경험에 따라 달라질 수 있다는 점, 촬영·공개 권한과 얼굴 가림, 초기 제보 부족을 모의 데이터로 설명할 필요가 언급됐다. Moovit과 Mapillary가 비교 사례였다.

## 고령 운전자: 운전 예고편

근거: [M025–M028](archive/conversation-04.md#m025).

초기 후보는 낯선 길을 미리 경험하는 운전 예고편, 혼동 도로 개선, 주행 복기·교육, 운전 대체 이동수단 추천이었다. 사용자는 첫 두 후보에 관심을 보였지만 **도로 자체 개선은 확장 가능성으로 남기고, 운전 대체 추천은 핵심에서 제외**하자고 했다. 운전 제한으로 받아들여질 가능성을 우려한 판단이지 모든 고령자의 성향을 확인한 결과는 아니다.

남은 서비스는 목적지 입력 → 빠른 길과 단순한 길 비교 → 어려운 교차로·차선 변경 구간을 사진·영상으로 사전 확인 → 기존 내비게이션으로 주행하는 방식이다. “처음 가는 길도, 미리 가본 길처럼”이 제안 문구였다.

AI 역할은 도로 영상 특징 추출, 복잡도 분석, 미리 볼 구간 선택, 개인 선호를 반영한 순위 조정이다. 사용자 혼동 제보를 향후 도로 개선 후보 자료로 쓸 가능성은 유지했다. 운전 중 영상 재생, 나이·운전 능력 점수화, 영상만으로 위험을 확정하는 방식은 답변에서 배제하거나 경계했다. 실제 운전자 시점 영상과 사용권 확보가 우선 과제였다.

## 농촌 고령자 폭염과 그늘길

근거: [M029–M030](archive/conversation-04.md#m029).

사용자는 폭염을 피할 그늘길 지도를 생각했지만 농촌의 어르신에게 실제 의미가 있을지 질문했다. 답변은 길가·논밭·집이라는 발생 장소를 나누고, 그늘이 부족한 농촌에서는 경로만으로 해결되지 않는다고 보았다.

대안은 **더위쉼표**라는 가칭의 시간·장소·이동 추천이다. 외출 시간 조정, 실제 운영하는 쉼터, 그늘·거리·휴식 장소를 함께 고려하는 경로, 농작업·실내 냉방 문제를 별도로 다루자는 제안이었다. 자녀·이장·생활지원사 등 돌봄 관계자를 보조 사용자로 두는 관점도 나왔다. 쉼터의 물리적 거리 외에 운영 여부·이용 대상·실제 접근성, 스마트폰 접근성, 당사자 동의가 검토 항목이었다.

## 재난 비서의 첫 등장

근거: [M031–M032](archive/conversation-04.md#m031).

사용자는 집에 두는 음성 비서가 홍수·태풍 때 대피로를 안내하는 서비스를 제안했다. 답변은 가칭 **안심이**, “재난 상황에서, 누구도 혼자 판단하지 않도록”으로 설명했다.

평소 대피계획 등록 → 재난 경보와 개인 이동 상태 확인 → 경로 또는 도움 요청 → 대피 후 안전 확인의 흐름이다. 안전디딤돌, 응급안전안심서비스, AI 돌봄 스피커와 비교하면서, 길 자체보다 **그 사람이 실제로 대피할 수 있는지**를 핵심으로 잡았다. 처음의 가정용 기기 안은 나중에 사용자가 모바일 앱으로 변경했다.

## 고령자 범죄 질문에서 사회적 연결로

근거: [M033–M036](archive/conversation-05.md#m033).

사용자는 61세 이상 범죄 증가 뉴스의 배경을 묻고, 사회적 고립·심리적 문제를 서비스로 완화할 수 있는지 질문했다. 답변은 전체 건수·피의자 비중·인구당 발생률과 개별 범죄 유형을 구분하고, 인구 고령화 외의 경제·관계 요인을 가능한 설명으로 다뤘다. 해당 통계와 원인 설명은 원문에 보존했으며 이 문서에서 새로 검증하지 않았다.

후보는 경험과 사회적 역할 매칭, 갈등을 정리하는 마음의 통역사, 관계 형성 추천이었다. 결합안 **동네에 내 자리**는 음성으로 경험 파악 → 지역의 검증된 사람·활동 추천 → 연결 이유 설명 → 자발적 후속 만남의 흐름이다. 실제 관계 형성과 고립 완화를 목표로 삼으며 범죄 예측·감시·범죄 감소 효과를 주장하는 서비스로 만들지 않는다는 의견이 포함됐다.

## 다시 일상 문제에서 출발한 후보

근거: [M037–M038](archive/conversation-05.md#m037).

| 문제 | 제안 서비스 |
| --- | --- |
| 서류가 빠져서 헛걸음 | 목적과 개인 조건에 맞는 준비물·기관·절차 추천 |
| 키오스크에서 무엇을 누를지 모름 | 카메라 화면과 사용자 목적을 이해해 다음 버튼 안내 |
| 공지를 읽어도 할 일을 놓침 | 행동·기한·준비물·접수처를 체크리스트로 전환 |
| 어디에 문의할지 모름 | 문제와 관할을 분석해 담당 기관·채널·증빙 추천 |
| 물건 사진에 내 정보도 찍힘 | 게시 목적에 불필요한 개인정보 가림 제안 |
| 파일의 숨은 정보가 유출됨 | 숨김 시트·메타데이터·발표자 노트와 민감 문맥 점검 |
| QR이 공식 것인지 불분명 | 연결 URL·안내문·등록 정보 비교로 의심 징후 설명 |

공통 관점은 “정보가 없는 것이 아니라, 있는 정보를 현재 상황의 행동으로 연결하기 어렵다”였다. 사용자는 이후 1인 가구·어르신의 재난 대피 비서로 돌아와 추천 주제와의 연결을 구체화했다. 그 이후는 [서비스 문서](02-service-and-recommendation.md)로 이어진다.
