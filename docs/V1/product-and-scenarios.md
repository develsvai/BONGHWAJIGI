# 서비스 목표와 사용자 시나리오

봉화지기는 여러 출처에서 수집한 재난 정보를 바탕으로 사용자에게 관련 상황과 필요한 행동을 알려주는 모바일 재난 대응 가이드입니다. 공식 경보 전달과 함께, 주변 지역의 사건이 현재 위치에 영향을 줄 가능성을 살펴봅니다.

## 문제와 공공성

재난 안내를 받아도 자신의 위치에 어떤 영향이 있는지, 이동할 수 있는 길인지, 도움을 요청해야 하는지 판단하기 어려울 수 있습니다. 특히 이동에 제약이 있거나 낯선 지역에 있는 사람에게는 같은 문구를 전달하는 것만으로 충분하지 않습니다.

공공성의 중심은 정보 접근과 대응 기회의 격차를 줄이는 데 있습니다.

- 글을 읽기 어려운 상황에서도 음성으로 핵심 행동을 전달합니다.
- 이동 능력과 지원 필요에 맞는 행동을 안내합니다.
- 행정구역 경계 밖의 사건도 실제 영향 경로가 연결되면 관련 정보를 제공합니다.
- 안내의 근거, 발표·관측 시각, 확인되지 않은 사항을 보여줍니다.
- 낯선 지역 방문자가 주변 경로와 적절한 대피 장소를 이해하도록 돕습니다.

## 사용자 범위

사용자가 제시한 초기 시나리오는 아래 세 가지입니다. 회의 후반에는 일반 시민과 낯선 지역 방문자까지 필요성을 확장했습니다. 첫 시연의 주요 대상은 UI/UX와 함께 최종 결정합니다.

| 초기 시나리오 | 평소 확보할 조건 | 안내에서 달라지는 부분 |
| --- | --- | --- |
| 혼자 보행 가능한 1인 가구 | 현재 위치, 이동 가능 여부, 필요시 연락 대상 | 스스로 실행할 수 있는 행동과 경로, 응답·도착 확인 |
| 계단 이용이 어려운 어르신 | 계단·경사 제한, 보행 보조 여부, 이동 준비 시간 | 계단 등 이용 불가 구간 제외, 적절한 준비·이동 시점 |
| 자력 대피가 어려운 어르신 | 이동 지원 필요, 연락 가능한 보호자·지원자, 지원 소요 시간 | 지원 요청과 수신 확인, 상황에 맞는 대기·보호 행동 |

1인 가구 여부, 나이, 보행 능력, 지원 필요 여부는 별도 속성으로 관리하는 제안입니다. 혼자 사는 사람이 동시에 계단 이용이나 자력 대피에 어려움을 가질 수 있습니다. 나이만으로 이동 능력을 정하지 않습니다.

## 서비스 원칙

| 상태 | 원칙 |
| --- | --- |
| 요구사항 | AI의 임의 판단을 금지합니다. AI 기능 사용 자체를 금지한다는 뜻은 아닙니다. |
| 요구사항 | 여러 기관의 검증 가능한 재난 자료와 주변 사건 정보를 활용합니다. |
| 요구사항 | 새로 확보한 정보를 빠르게 반영해 사용자가 지금 무엇을 해야 하는지 돕습니다. |
| 회의 방향 | 서비스는 재난 대응 가이드로 설명하고 AI는 내부 특정 기능에 사용합니다. |
| 회의 방향 | LLM은 안내 문장 생성에 한정하고 데이터 선별·위험 판단은 별도로 처리합니다. |
| 설계 제안 | 공식 경보와 서비스 자체 주의·대응 안내를 화면과 데이터에서 구분합니다. |
| 설계 제안 | 긴급한 공식 지시 전달은 모델 분석이나 3D 로딩을 기다리지 않습니다. |
| 설계 제안 | 위치와 프로필을 평소부터 반영하며, 실제 행동 안내 시 최근 상태를 다시 확인합니다. |

## 사용자별 대응의 의미

주변 재난이 특정 위치에 도달할 가능성과 사용자가 대응하는 데 필요한 시간은 구분합니다. 같은 위치에 있는 두 사람의 이동 능력이 다르다고 물리적인 확산 확률을 임의로 바꾸지 않습니다. 준비 시간, 사용 가능한 경로, 지원 요청 시점이 달라지는 구조입니다.

재난 유형과 공식 지침에 따라 이동, 실내 보호, 준비, 지원 요청 등 적절한 행동을 선택해야 합니다. 모든 위험 상황을 일괄적으로 대피 명령에 연결하지 않습니다. 구체적인 행동 문구와 선택 조건은 해당 재난의 매뉴얼을 확인해 정해야 합니다.

## 주변 지역 사건을 반영하는 예시

다음은 동작을 설명하기 위한 가상 시나리오이며 실제 경보나 검증된 예측 수치가 아닙니다.

1. 사용자가 있는 구역 밖에서 산불 관련 정보가 들어옵니다.
2. 위치·시각이 맞는 공식 발표, 기상 관측, 관련 보도를 연결합니다.
3. 풍향과 지형 등 확보된 자료로 사용자 지역과의 관련성을 평가합니다.
4. 현재 위치에 직접 경보가 없어도, 정책 조건을 만족하면 근거를 붙여 주의나 준비 안내를 제공합니다.
5. 이동에 시간이 필요한 사용자는 준비·지원 요청 시점을 달리 평가합니다.
6. 공식 지시나 새 관측이 들어오면 행동과 경로를 다시 검토하고 변경 이유를 알립니다.

자료가 부족하면 영향 여부를 미확인으로 남깁니다. 관련 기사가 많다는 이유만으로 확산을 확정하지 않습니다.

## 해커톤 범위 제안

현재 제안은 **한 지역, 한 재난 유형, 세 가지 사용자 상황**으로 제한하는 것입니다. 회의에서는 산불 중심 사례와 건물 내부 시연 축소안이 모두 나왔으므로 재난·공간 범위를 확정한 것으로 취급하지 않습니다.

최소 시연에는 수집, 사건 연결, 위치 관련성 평가, 사용자별 대응 선택, 근거 설명, 경로·음성 안내, 상황 변화에 따른 재안내를 포함하는 방안을 제안합니다. 실제 자료와 재현용 시뮬레이션 입력은 구분해 표시합니다.

카메라를 통한 주변 물체 인식, 정밀 실내 위치 추정, 모든 재난 유형 지원, 자동 구조기관 연계, 전국 대규모 운영은 별도 검토 항목입니다.

## 검증할 효과

- 공식 경보만 표시하는 기준 흐름과 비교한 관련 정보 전달 시점
- 사용자당 불필요한 알림 빈도와 중요한 사건 누락
- 예측 수치와 실제 관측 결과의 일치 정도
- 근거·발생 시각·위치 추출의 정확도
- 사용자별 이용 불가 경로를 추천하지 않는지 여부
- 안내 확인, 지원 요청 수신, 행동 완료를 구별해 추적하는지 여부

목표 수치는 데이터와 시연 범위를 결정한 뒤 설정합니다.
