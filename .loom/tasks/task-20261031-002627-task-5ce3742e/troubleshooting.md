# 문제와 남은 검증

클러스터에서 두 제공 서버의 TCP 22는 모든 시험 위치에서 시간 초과였다. 노드 경로는 일반 게이트웨이를 사용했고 제공 서버 대역의 전용 경로는 보이지 않았다. 사용자가 별도 VPN임을 확인했으므로 VPN 분리의 예상 결과로 기록했다. A3에서 명시적으로 연결 방법을 정해야 한다.

GPU 서버에 초기화·메모리 검사 실패는 없었다. mlnx_interface_mgr는 ifup이 설치된 상태에서 누락된 /etc/network/interfaces를 사용하는 분기에 들어가는 설치 스크립트와 부팅 실패 로그가 일치했다. 현재 netplan/networkd 네트워크와 실제 연결은 정상이다. Fabric Manager의 상태는 masked/failed이며 단일 L4에서 현재 CUDA 동작을 막지 않았다. 두 서비스의 상태 정리는 수행하지 않았다.

일반 서버는 이번 접속에서 자격 증명을 정확히 판독·인증하지 못해 재조회에 실패했다. 작은 첨부 이미지의 OCR은 기본 제한 환경에서 오류가 났고 권한 있는 판독으로 텍스트를 확인했으나 로그인은 성공하지 못했다. 추가 반복을 중단하고 SSH를 종료했다. A0의 성공한 내부 조회와 이번 인증 결과를 구분했으며 비밀번호 변경이나 VPN 문제로 단정하지 않았다. 모든 OCR 및 인증 값은 실행 중 메모리에서만 사용하고 저장소 산출물에서 제외했다.

마스터 resolver에는 nameserver 네 개가 있어 일부 생략 경고가 반복된다. 이번 DNS 및 HTTPS 시험은 통과했지만 resolver 정리는 별도 변경 검토가 필요하다. 높은 재시작 횟수는 과거 종료 시각과 관찰 구간의 증가 없음으로 현재 장애와 구분했다.

다른 검증 Task의 계약 검사 OK는 선행 산출물의 존재를 보장하지 않았다. 실제 의존 Task 상태와 출력 경로를 별도로 대조해 C4/D3/E2/A4를 PENDING으로 유지했다.
