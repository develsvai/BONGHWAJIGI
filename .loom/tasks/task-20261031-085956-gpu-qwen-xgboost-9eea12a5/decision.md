# 실행 결정

- 기존 L4 1대를 사용하고 일반 시스템·Python과 다른 서비스는 유지했다. 사용자 새 프로젝트 경로, .venv-gpu와 .venv-ml을 분리하고 저장소 uv.lock으로 설치했다.
- 모델 revision 두 개를 고정하고 실행 중에는 로컬 캐시만 사용한다. 생성·임베딩을 같은 단일 프로세스에 BF16으로 올리고 GPU 요청을 직렬화했다. 임베딩은 float32에서 다시 단위 정규화했다.
- 새 서비스 토큰을 서버에서 생성해 600 파일에 저장했다. API는 localhost에만 바인딩한다. 사용자 systemd 서비스 및 linger를 사용해 관리 SSH 종료 후에도 유지한다. 토큰·SSH 비밀번호를 저장소나 보고서에 넣지 않았다.
- 동일 사용자 GPU 잠금으로 Qwen 상주와 XGBoost 학습의 동시 실행을 막았다. XGBoost는 합성 CUDA 검사만 수행하고 산불 정답·예측 목표·정책 레벨을 임의로 확정하지 않았다.
- 실제 K8s 수집 없이 시나리오를 재생한다는 사용자 지시를 유지했다. 이번에는 모델 준비만 수행하고 일반 서버 DB·큐·수신 기능을 완료로 바꾸지 않았다. Verified Team Policy Snapshot은 없다.
