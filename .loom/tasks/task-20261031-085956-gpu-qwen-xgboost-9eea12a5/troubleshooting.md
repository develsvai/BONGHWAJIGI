# 확인 및 해결

- 공식 uv 설치 스크립트 주소는 서버에서 403이었다. 공식 PyPI uv 0.11.10 wheel을 받아 SHA256을 확인한 후 바이너리만 사용자 영역에 설치했다. 전역 pip나 시스템 패키지를 변경하지 않았다.
- 최초 tar 전송의 macOS 확장 속성 헤더는 Linux가 무시했다. 이후 Python USTAR 아카이브로 코드만 다시 전송해 불필요한 메타데이터를 제외했다.
- 로컬 첫 패치에 동일 경로 삭제/추가가 함께 있어 도구가 전체 패치를 거부했다. 파일 수정은 적용되지 않았고 이후 정상적인 update 패치로 반영했다.
- 설치 조합의 torch_dtype/tokenizer_kwargs 경고를 dtype/processor_kwargs로 수정했다. BF16 임베딩 정규화 오차는 float32 재정규화로 줄인 뒤 실제 API 검증을 다시 통과했다.
- XGBoost wheel은 CUDA 13.3 빌드였으나 실제 드라이버 580.159.04의 L4에서 합성 cuda:0 학습과 CPU 재로딩이 통과했다. 문서의 최소 CUDA 요구만으로 성공을 가정하지 않았다.
- Starlette TestClient의 httpx 전환 안내 경고 1개는 남아 있지만 12개 로컬 테스트와 실제 원격 HTTP 검증은 통과했다. 실제 재부팅과 대규모 자료 품질·부하 검증은 후속 범위다.
