# 결정

사용자가 현재 에이전트에게 레포 확인과 스택 선정을 직접 지시하여 기존 V2 실행 기반 Job에 문서화 Task를 추가하고 foreground 세션을 열었다. 구현·설치·학습 실행으로 범위를 넓히지 않았다.

일반 서버의 기존 2 vCPU·약 8GiB 기록과 단일 L4 GPU, OpenAPI 초안 및 공식 경보 우선 경로를 기준으로 Python 중심 스택을 정했다. 하나의 PostgreSQL에서 관계·공간·벡터 자료를 함께 관리하고 큐별 전용 워커와 outbox·중복 키로 처리 상태를 보존한다.

GPU 첫 서빙은 Transformers/Sentence Transformers를 한 프로세스로 묶고 동시 요청을 제한한다. 설치 및 처리량 검증 전 자원 가용성을 보장하지 않는다. 모델 환경과 API/수집 환경은 분리하고 구현 시 패치·이미지·모델 revision을 고정한다.

사용자는 대응 레벨과 레벨별 알림 방식이 회의 중이라고 밝혔다. 이를 미정으로 명시하고 정책 선택은 검토된 Python 규칙으로, Qwen은 사실 추출·선택된 행동 설명으로 한정했다. 정책 임계값을 이 기술 결정에 포함하지 않았다.

기존 구현 A3에 이 문서와 설계 Task를 연결하고 B/C/D/E에는 관련 Job 노트로 인계했다. 다른 구현 Task의 상태·Queue와 _APP은 변경하지 않았다.
