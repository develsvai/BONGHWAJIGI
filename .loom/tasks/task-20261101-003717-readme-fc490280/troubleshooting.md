# 확인 및 복구

- 최초 Task 등록에서 README를 일반 docs 출력과 예외 양쪽에 넣자 CLI가 docs 밖 일반 출력을 거부했다. 사용자 요청대로 루트README를 예외 출력으로만 선언해 정상 등록·실행했다. 승인 필요 조건으로 확대하지 않았다.
- 아키텍처 원본은 첫 열람 시 존재했고 SHA256 `ce85970809093b937d694ec3a298f7981e5b0057462b87904689aca827a8dba2`를 확인했다. 이후 Downloads에서 사라졌지만 저장소의 `original-style-current.png`가 같은 SHA여서 기존 파일을 재사용했다. 원본을 다시 요청하거나 삭제를 복원하지 않았다.
- Tailnet readiness는200이었고 app-config의 무인증 요청은401로 거부됐다. 사용자 API를 공개 경로라고 쓰지 않고 세션/JWT가 별도로 필요함을 반영했다.
- 기존 운영 문서에는 초기의 HTTPS·단말 미검증 표현이 남아 있다. README는 최신 배포·촬영 검증을 우선하고 초기 문서의 적용 시점을 표시했다. 오래된 문서를 임의 삭제하거나 다른 채팅의 삭제를 되돌리지 않았다.
- 검증에서 기존 Starlette/httpx 사용 중단 경고1개가 있었다. 이번 문서의 검사 결과와 무관한 기존 의존성 경고이며 런타임을 변경하지 않았다.

현재 README 완성·검증에 대한 차단 사항은 없다. 실제 새 배포·단말 추가·FCM 및 예측 연결은 각 담당 작업 범위다.

공용 events.jsonl의 기존 부분도 다른 작업에서 수정되어 prefix 기반 안전검사가 최초 스테이징을 중단했다. 작업 파일을 되돌리지 않고 HEAD의 기존 이력과 이번 Task의 새 이벤트만 Git 인덱스에 합치는 방식으로 복구했다. 다른 작업의 이벤트 편집·삭제는 워킹트리에 유지한다.

자동 승인 검토가 공용 이벤트의 다른 기록 제거 위험을 이유로 커밋을 거절했다. 읽기 전용으로 실제 후보 diff를 대조하여 삭제0줄·HEAD377줄 전체 바이트보존·현재Task4줄만 추가임을 확인했다. 해당 불변조건을 스테이징 코드에 명시하고 이 근거로 재검토를 요청한다. 공유 워킹 파일은 수정하지 않는다.
