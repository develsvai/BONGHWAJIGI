# 실행 결과

사용자가 확정한 3단계와 최종 명칭 1 경고/2 대피/3 위급을 고정 실행기로 구현했다. 기본 지침 10개를 출처·검토 상태·30일 유효기간과 함께 DB에 등록하고 사용자 이동 지원·동반자·현재 이동 가능·조력자·경로 상태에 따라 행동을 선택한다. H3와 3단계를 구분하며 실제 예측 값이나 Qwen 생성문을 단계 결정에 사용하지 않는다.

공식 urgent 수신·DB/outbox·독립 Celery 큐·원문/대상 저장과 정정/취소·역순 거부를 구현했다. 사용자별 변경 cursor·기기·알림 DB, 독립 전달 큐, 임대/최대 5회 재시도·기기 회전/해제·옛 revision 억제 및 FCM HTTP v1/모의 발신기를 추가했다. 모의 성공·제공자 수락·단말 수신/열람을 구분한다.

## 검증

실제 PostgreSQL의 새 migration 적용, Alembic check, 73개 전체 테스트 통과. 세 사용자·조력자 확보·경로·확인 후 하향, GPU 없는 공식 경보·중복·취소, 전달 재시도와 기기 해제, FCM 429/503/UNREGISTERED/INVALID_ARGUMENT·제공자 수락·자격 파일 권한을 검증했다. Ruff 정적/포맷, 기존 25 API/67 스키마/48 HTTP 예제/4 오류 거부 및 Loom strict도 통과했다. 기존 Starlette/httpx 경고 1개만 남는다.

## 범위와 다음 연결

사용자는 Firebase·테스트 단말이 없어 모의 전송까지만 요청했고 HTTPS 도메인 없이 사설망 개발 서버 배포를 선택했다. 실제 FCM/단말 전송이나 119 신고는 하지 않았다. 실제 예측 모델 연결, GPU 학습, 앱 저장소는 변경하지 않았다. 앱용 인증/API와 실제 일반 서버 배포는 별도 승인된 후속 Task에서 계속한다. 문서는 docs/V2/delivery/response-policy.md이며 V3와 최초 루프 문서에 후속 확정을 연결했다.
