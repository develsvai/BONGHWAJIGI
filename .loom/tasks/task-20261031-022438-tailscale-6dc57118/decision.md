# 결정

- 사용자가 두 서버 Tailscale 설정을 직접 지시했으므로 이전 읽기 전용 점검 범위와 구분해 설치·등록을 진행했다. 접근 정책은 브라우저 저장 직전에 구체적 출발지·목적지·포트를 제시해 사용자 승인을 받고 반영했다.
- 기존 네트워크 영향을 줄이기 위해 DNS 수용과 외부 서브넷 경로 수용을 끄고 Exit node, 서브넷 광고, Tailscale SSH는 활성화하지 않았다.
- 빈 수신 허용 규칙을 확인한 뒤 두 서버 IPv4의 TCP 22에 한정된 grant를 추가했다. 기존 정책은 유지하고 타 서비스 사이드카에는 신규 권한을 주지 않았다.
- 클러스터 전체에 Tailscale이 설치되었다고 해석하지 않는다. 마스터의 호스트 연결과 일부 서비스의 userspace 사이드카가 있는 상태이므로 프로젝트 수집 파드의 egress는 A3의 배포 구성으로 남긴다.
- 패키지는 공식 Ubuntu 저장소를 사용했다. 키는 숨김 입력과 표준 입력 전달로 처리하고 저장소·명령 인자·파일에 키 값을 넣지 않았다.
- 기존 A2 보고서는 당시 실패를 보존하고 최상단에 최신 연결 보고서 링크를 추가했다. 실행 작업표에는 A5와 후속 범위를 반영했다.
