# 미해결 항목과 복구

기본 실행 환경에서 원격 네트워크 접근이 거절됐다. 읽기 전용 네트워크 권한으로 재시도하여 K8s와 두 SSH 포트의 접근을 확인했다.

SSH 비밀번호를 터미널에 전달하는 단계는 처음에 자동 승인 검토에서 거절됐다. 검토기가 사용자 메시지에서 비밀번호와 전송 승인을 확인하지 못했다는 사유였다. 별도 질문에 사용자가 두 서버 로그인을 승인한 뒤 인증과 내부 조회를 완료하여 이 차단은 해소됐다. 승인 전 다른 도구나 간접 실행으로 우회하지 않았다. 인증정보는 파일, 보고서, 작업 로그에 남기지 않았다.

일반 서버는 최초에 로컬 호스트 키가 없어 엄격한 키 검사 단계에서 종료됐다. 승인 후 첫 호스트 키를 로컬 임시 known_hosts에 등록하고 이후 엄격한 검사를 적용했다. 로그인 후 호스트명이 제공 자료와 일치함을 확인했다. 재시도 중 일시적인 연결 시간 초과가 있었으나 포트 재확인과 후속 접속은 성공했다.

GPU 서버는 CUDA 초기화와 장치 조회가 성공했지만 systemd는 degraded다. mlnx_interface_mgr@eth0의 설정 파일 누락과 nvidia-fabricmanager의 NVSwitch 조회 실패는 10월 20일 부팅 로그에서 확인했다. 현재 서비스의 필요 여부와 영향은 A2에서 확인하며 이번에는 서비스 또는 드라이버를 변경하지 않았다. 기본 Python 환경의 주요 모델 패키지 미확인은 D3 환경 준비의 입력이다.

클러스터 마스터의 DNSConfigForming은 nameserver 제한 초과에 따른 일부 DNS 생략 경고다. 현재 Ready 상태와 별도로 실제 DNS 해석 영향은 A2에서 확인한다. 높은 누적 재시작은 과거 종료 시각으로 현재 장애와 구분했다.

기존 문서 5개의 V1 이동과 HeoNey의 미완료 문서화 상태는 이번 작업의 수정 범위가 아니므로 그대로 유지했다. 이번 결과는 전체 저장소가 깨끗하다는 주장이 아니다.
