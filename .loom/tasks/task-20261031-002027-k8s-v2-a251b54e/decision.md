# 결정

- 사용자는 V2를 설계 기준으로 지정했고 HeoNey는 참고로만 두도록 했다.
- 사용자는 서버 클러스터 조회와 TODO의 Job Task 등록을 현재 에이전트에게 직접 요청하고 분할 기준을 위임했다. 이 권한으로 실행 기반 데이터 모델 대응 서버 API 계약의 5개 Job을 생성했다.
- 기존 초기 문서화 Job의 목표와 신규 구현 산출물의 범위가 달라 별도 Job으로 구분했다. 단순 문서 작업을 중복 Job으로 쪼개지 않았다.
- 공식 경보 전달은 XGBoost 완료를 기다리지 않고, API 초안은 데이터 스키마와 대응 규칙 후 작성하도록 연결했다.
- 선택 기능의 포함 여부 결정과 조건부 구현을 분리했으며 양방향 음성 및 앱 화면 구현은 범위에 넣지 않았다.
- 조회는 읽기 전용으로 한정했고 기존 서비스를 설치 변경 재시작하지 않았다. 환경 경고는 후속 계약에 기록했다.
- 자격 증명 전송이 거절된 뒤 다른 인증 우회 방식으로 재시도하지 않았다. 사용자에게 명시적 승인을 요청하고 그 외 작업을 완료했다.
- 미래 작업의 필수 문서가 보존되도록 사용자가 제공한 V2 원문 3개를 변경 없이 계획과 함께 보존한다. 기존 V1 이동과 HeoNey 파일은 수정하거나 커밋하지 않는다.
