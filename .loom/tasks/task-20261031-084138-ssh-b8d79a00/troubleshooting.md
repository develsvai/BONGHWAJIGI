# 확인 사항과 해결

- 기존 ~/.ssh/config가 root 소유여서 단순 덮어쓰기 대신 백업 후 사용자 소유 .ssh 디렉터리에서 원자 교체했다. 기존 설정 바이트와 네 Host 항목의 유효 설정을 보존했다.
- 일반 서버의 Tailnet 주소는 기본 known_hosts에 없었다. 이전 VPN 접속 때 확인한 임시 known_hosts의 공개 키와 현재 서버 키가 일치함을 검증한 후 주소를 추가했다.
- 설정 전후 비교의 첫 실행에서 한쪽에만 -F를 적용해 시스템 설정 포함 조건이 달랐다. 양쪽 모두 같은 -F 조건으로 다시 비교해 기존 네 별칭의 유효 설정 전체가 같음을 확인했다.
- 임시 공개 키 파일 검색 중 무관한 codex-daemon 디렉터리는 접근 제한이었다. 기존 서버 키 파일은 정상적으로 확인했으며 접속 작업에 영향은 없다.
- 실제 로그인과 자원 조회는 두 서버 모두 성공했다. 미해결 접속 오류는 없다. 이후 장애는 Tailnet 온라인 상태·TCP 22 권한·호스트 키 대조 순으로 확인하며 API 통신은 A3의 별도 검증 대상이다.
